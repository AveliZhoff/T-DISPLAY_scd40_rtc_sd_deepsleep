# Design

## Context

См. `proposal.md` и delta `specs/device-lifecycle/spec.md`. Сейчас `setup()` определяет отображение по причине пробуждения и наличию USB; верхняя кнопка подключена к GPIO0, вторая — к GPIO35. Для настроенного пользователем режима нужно сохранить значение через перезапуск и отличать его от прежней автоматической политики.

## Goals / Non-Goals

**Goals:**

- Использовать GPIO35 как вторую кнопку для переключения режима и проверять длительное удержание только для пробуждений EXT0/EXT1.
- Не менять поведение цикла, в котором распознано переключение; применять новый режим при следующем старте.
- Сохранять ручной выбор после отключения питания, не меняя зависимости.
- Оставить прежнее автоматическое поведение, пока пользователь еще не выбрал режим.

**Non-Goals:**

- Изменять назначение кнопок, длительность deep sleep или сценарий измерения.
- Добавлять пользовательский интерфейс для смены режима помимо удержания кнопки.

## Decisions

- Хранить наличие ручного выбора и его значение в NVS через `Preferences`. При отсутствии сохраненной настройки использовать существующее правило выбора дисплея; после первого выбора сохраненное `on` или `off` имеет приоритет над состоянием USB и причиной пробуждения.
- На старте сначала вычислять режим, который действует для текущего цикла, по предыдущей сохраненной настройке или существующему правилу. Только при причине пробуждения EXT0/EXT1 проверять GPIO35: низкий уровень должен сохраняться целую секунду. После подтверждения переключить и сохранить противоположное значение, но не менять режим текущего цикла.
- Для сообщения временно включать дисплей на одну секунду, если иначе он был бы выключен, затем восстановить режим текущего цикла. Это позволяет сообщить и о выборе `display on`, и о выборе `display off`, не применяя новый режим до следующего старта.
- Считать GPIO35 активной низким уровнем; сообщение выбирать по новому сохраненному значению. Исключить повторное переключение от одного удержания, в том числе при повторном пробуждении, пока кнопку не отпустили.

## Risks / Trade-offs

- [Ручной `display on` может расходовать заряд при пробуждении по таймеру без USB] → Это ожидаемое следствие выбранной пользователем настройки; отдельного сброса к автоматическому режиму в рамках этого изменения нет.
- [При выборе режима `off` пользователь видит дисплей включенным во время подтверждения] → Краткое сообщение длится одну секунду; далее в том же цикле восстанавливается прежнее поведение, а сохраненный режим начинает действовать при следующем запуске.
