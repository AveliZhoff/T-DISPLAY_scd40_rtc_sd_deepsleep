# Design

## Context

Сон вызывается из нескольких ветвей `main.cpp`, но все они проходят через `enterDeepSleep()`. SCD-40 работает в режиме периодических измерений и запускается в начале следующей загрузки. SD-карта использует HSPI, а Arduino-библиотека SD предоставляет `SD.end()` для отмонтирования карты и освобождения ее ресурсов.

## Goals / Non-Goals

**Goals:**
- Гарантировать вызов завершения работы SCD-40 и SD перед единой точкой входа ESP32 в глубокий сон.
- Сохранить существующий порядок запуска периодических измерений в начале следующего цикла.
- Не терять завершенные операции очереди на SD при завершении работы карты.

**Non-Goals:**
- Физически отключать питание SCD-40 или SD-карты.
- Менять период измерений, формат записей или алгоритм буферизации.

## Decisions

- Сосредоточить очистку в `enterDeepSleep()`, чтобы она выполнялась для обычных и аварийных путей перехода в сон.
- Для SCD-40 использовать команду остановки периодических измерений. Драйвер помечает аппаратные `powerDown`/`wakeUp` команды как доступные только для SCD41, поэтому их нельзя использовать для установленного SCD40. При следующей загрузке уже существующий запуск датчика возобновит измерения.
- Добавить завершение работы SD-хранилища, вызывающее `SD.end()` только для смонтированной карты, затем завершать HSPI. Все операции хранения должны быть закончены до вызова этого завершения.
- Если команда остановки SCD-40 сообщает об ошибке, записать ее в Serial и все равно продолжить переход в сон; бесконечно удерживать контроллер активным ради неудачной команды нельзя.
- Не заявлять физическое отключение SD: в коде нет отдельного переключаемого вывода питания карты. Отмонтирование и остановка SPI прекращают использование интерфейса прошивкой, но не отключают линию питания карты.

## Risks / Trade-offs

- Команда остановки SCD-40 может завершиться ошибкой при проблеме I2C или датчика → записывать ошибку; продолжать предусмотренный переход в сон и повторно инициализировать датчик при следующей загрузке.
- Отмонтирование SD до завершения операции записи может повредить очередь → вызывать очистку только через общую точку сна после завершения всех текущих операций, сохраняя закрытие файлов в операциях хранилища.
- SD-карта остается под аппаратным питанием в глубоком сне → документировать ограничение; физическое управление потребует изменения схемы/оборудования.
