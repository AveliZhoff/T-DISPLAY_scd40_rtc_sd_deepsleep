# Design

## Context

See `proposal.md` for motivation and `specs/air-quality-monitoring/spec.md` for observable behavior. Значения CO2, температуры и влажности уже сохраняются между циклами в RTC-памяти. Модуль дисплея рисует только новое измерение, когда цикл датчика его получает.

## Goals / Non-Goals

**Goals:**
- Использовать сохраненные показания предыдущего цикла без добавления постоянного хранилища или зависимости.
- Переходить от серых предыдущих значений к текущим показаниям с существующей цветовой индикацией.

**Non-Goals:**
- Изменять усреднение, форматирование или цветовые диапазоны текущих показаний.
- Показывать измерения, когда дисплей отключен настройкой режима.

## Decisions

- Добавить в API дисплейного модуля отдельную операцию для показа предыдущего измерения и вызывать ее при старте цикла, когда дисплей уже готов и до получения нового измерения. Значения передавать из RTC-памяти; текущий путь `displayShowMeasurement` продолжит выводить новые значения и их цвета.
- Использовать серый цвет для всех трех предыдущих значений и оставить их в текущих областях измерений. Это исключает изменение компоновки и позволяет заменить их свежими значениями без дополнительной строки.
- Показывать предыдущий набор только при валидности полного измерения: необходимы сохраненные CO2, температура и влажность. Если данные невалидны или дисплей выключен, не рисовать их.

## Risks / Trade-offs

- [Ранний вывод может быть очищен последующими экранными сообщениями при старте] → Вызывать отрисовку после операций инициализации, очищающих экран, но до ожидания нового измерения; проверить переход как при обычном пробуждении, так и при холодном старте.
- [Данные RTC могут быть неполными при первом цикле или после сброса] → Проверять флаг валидности полного набора и оставлять значения пустыми до первого нового измерения.
