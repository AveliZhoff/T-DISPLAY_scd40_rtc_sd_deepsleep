# Design

## Context

Сейчас `setup()` получает строки даты и времени из RTC и обновляет их после NTP-синхронизации. Полный показ времени выполняется только при старте, не являющемся пробуждением из deep sleep. Функция вывода рисует текст по центру экрана шрифтом TFT_eSPI №4 на Y=56 и Y=84 и хранит последние строки для стирания.

## Goals / Non-Goals

**Goals:**

- Поддержать требуемую видимость и последовательность RTC/NTP времени без очистки остального экрана.
- Стирать только две строки даты и времени, не затрагивая статусы и измерения.
- Сохранить существующий формат и геометрию вывода.

**Non-Goals:**

- Изменять часовой пояс RTC, алгоритм выбора NTP-серверов или UTC timestamp измерений.
- Менять условия включения дисплея или существующие статусы компонентов.

## Decisions

- Использовать существующие центрирование, шрифт и координаты даты/времени; добавить согласованный способ погасить ранее показанные строки цветом фона.
- Проверять и обрабатывать потерю питания RTC при запуске, когда дисплей включен. В сценарии потери питания немедленно инициировать NTP-синхронизацию, сохраняя исходные строки RTC красными до ответа; после успешной синхронизации стереть именно исходные строки и затем показать NTP-значения зеленым. Это сохраняет заданный порядок даже при быстром ответе NTP.
- Для показа, который не заменяется успешным результатом NTP, выдерживать 3 секунды, затем стирать те же строки цветом фона. После вывода синхронизированных значений также выдерживать 3 секунды до их очистки.
- Не очищать весь экран для временного показа: полный экран используется сообщениями о запуске, поэтому локальная очистка двух строк минимизирует визуальные побочные эффекты.
- Считать первым запуском контроллера запуск, не являющийся пробуждением из deep sleep; при валидном RTC на таком запуске показывать его время зеленым.

Альтернатива — обновлять часы постоянно. Она не выбрана, поскольку требование задает кратковременный показ с явной очисткой, а постоянный вывод потребовал бы менять поведение основного экрана.

## Risks / Trade-offs

- Синхронный NTP-запрос может задержаться; красные исходные значения останутся видны до завершения запроса, после чего будут стерты перед зелеными значениями. Это соответствует выбранному порядку перехода и не требует фоновой задачи.
- Трехсекундное удержание даты/времени задерживает последующие действия во время запуска. Задержка ограничена кратким показом и не добавляет новых зависимостей.
