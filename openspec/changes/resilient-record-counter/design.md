# Design

## Context

См. `proposal.md` — Why. Очередь на карте — единственное место, где хранятся неотправленные
измерения; устройство питается от аккумулятора и засыпает в deep sleep каждые несколько минут,
поэтому обрыв питания посреди файловой операции — штатный сценарий, а не исключение.
Файл `src/sd_storage.cpp` работает поверх Arduino-обёртки SD (SdFat), которая поддерживает
`rename`, `remove`, `size` и `flush`, но не даёт транзакций.

## Goals / Non-Goals

**Goals**
- Счётчик записей всегда соответствует корректному содержимому файла: после сбоя питания,
  жёсткой перезагрузки, замены карты и внешней правки.
- Очередь не застревает из-за недописанной строки и не исчезает при удалении отправленных записей.
- Сохранить число обращений к карте в рабочем цикле: счётчик нужен в каждом цикле, полное
  чтение файла — только при холодном старте и ремонте.

**Non-Goals**
- Формат CSV, набор полей и интерфейс `sd_storage.h` не меняются.
- Полноценный журнал транзакций (WAL) и контрольные суммы файла не вводятся: стоимость записи
  и объём кода не оправданы для очереди из десятков строк.
- Восстановление данных, физически потерянных картой, не выполняется.

## Decisions

**1. Счётчик сверяется по размеру файла, а не только по маркеру в RTC-памяти.**
В RTC-памяти рядом с количеством хранится размер файла. Кэш действителен, если маркер на месте
и размер совпадает. Альтернатива — всегда перечитывать файл: надёжно, но это чтение на каждом
пробуждении (десятки килобайт на 1 МГц), что противоречит цели сокращения времени бодрствования.
Проверка размера — одно открытие файла без чтения содержимого.

**2. При монтировании карты счётчик всегда пересчитывается.**
Монтирование происходит один раз за цикл и только когда карта реально нужна (отправка или
сохранение). Это единственная точка, где можно дёшево поймать последствия сбоя питания, поэтому
экономить здесь нечего. Кэш используется только внутри цикла.

**3. Оборванная строка определяется по отсутствию завершающего перевода строки.**
Чтение идёт посимвольно (`readLine` с флагом `terminated`), поэтому «огрызок» в конце файла
отличается от полной строки без эвристик и без доверия к `readStringUntil`. Неразборчивость
(меньше восьми разобранных полей) проверяется отдельно тем же разбором, что и при загрузке.

**4. Ремонт файла — перезапись только корректных строк через temp и безопасную замену.**
Ремонт вызывается лениво: при монтировании, если найдены некорректные строки, и при загрузке
очереди. Альтернатива — удалять «хвост» через `truncate`: SdFat не даёт надёжного усечения на
всех картах, а перезапись использует уже проверенный путь замены файла.

**5. Замена файла идёт через резерв (`/measurements.bak`), а не «удалить и переименовать».**
Порядок: подготовить temp → увести основной в bak → подставить temp → удалить bak. При сбое
подстановки выполняется обратное переименование bak → основной. Восстановление при монтировании
приоритет отдаёт temp (он записан полностью), затем bak. Альтернатива — держать две копии
и переключать указатель: усложняет чтение и не даёт выигрыша на таких объёмах.

**6. Добавление записи проверяется по числу записанных байт и приросту размера файла.**
Строка форматируется в буфер один раз, пишется одним `write`, затем `flush` до закрытия.
Проверка ловит неполную запись сразу, а не в следующем цикле, и сбрасывает кэш, чтобы счётчик
не разошёлся с файлом.

**7. Хостовые тесты на заглушках Arduino/SD.**
Логика хранилища проверяется на ПК под g++ (`test/host/`): заглушки `Arduino.h`, `SD.h`,
`SPI.h` и файловая система в памяти (`host_fs.cpp`) позволяют имитировать потерю питания
(сброс RTC-памяти, обрыв записи, сбой переименования) без платы. Альтернатива — тесты только
на устройстве: медленно, не воспроизводимо, не покрывает сбои.

## Risks / Trade-offs

- [Пересчёт при каждом монтировании добавляет чтение файла] → монтирование выполняется только
  на циклах, где нужна карта, и файл читается один раз; на циклах без отправки карта не поднимается.
- [Дополнительный файл `/measurements.bak` занимает место на карте] → резерв существует только
  на время удаления отправленных записей и удаляется сразу после успешной подстановки.
- [Проверка размера файла не ловит правку с тем же размером] → такой сценарий требует внешнего
  редактора, меняющего байты без изменения длины; при загрузке очереди строки всё равно
  проверяются разбором, а некорректные вычищаются.
- [Потеря питания ровно между подготовкой temp и уводом в bak] → основной файл не тронут,
  temp удаляется при следующем монтировании; данные не теряются.
- [Хостовые заглушки не повторяют поведение конкретной карты] → тесты покрывают логику, а не
  драйвер; финальная проверка на устройстве остаётся в задачах.

## Migration Plan

Изменение не требует миграции данных: файл `measurements.csv` прежнего формата читается как есть.
При первом запуске новой прошивки оборванные строки, если они были, вычищаются автоматически.
Откат — возврат предыдущей прошивки; файл записей остаётся совместимым.
