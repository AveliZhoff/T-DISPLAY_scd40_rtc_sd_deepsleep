# Spec Delta

## ADDED Requirements

### Requirement: Восстановление счётчика записей по содержимому карты

При каждом монтировании SD-карты устройство MUST пересчитывать количество записей по файлу
`/measurements.csv`, не используя значение из предыдущего цикла. Кэш счётчика в RTC-памяти
MUST считаться действительным только при совпадении сохранённого в нём размера файла с текущим
размером файла.

#### Scenario: Холодный старт после потери питания

- GIVEN устройство потеряло питание и RTC-память со счётчиком
- WHEN карта смонтирована и в `/measurements.csv` есть записи
- THEN счётчик равен числу корректных записей в файле

#### Scenario: Подмена карты или внешняя правка файла

- GIVEN в RTC-памяти сохранён счётчик с размером файла, отличным от текущего размера
- WHEN устройство запрашивает количество накопленных записей
- THEN оно пересчитывает счётчик по файлу и возвращает фактическое значение

#### Scenario: Счётчик совпадает с файлом

- GIVEN сохранённый размер файла совпадает с текущим и файл не менялся
- WHEN устройство запрашивает количество записей
- THEN оно использует значение из RTC-памяти и не перечитывает файл целиком

### Requirement: Отбраковка оборванных и неразборчивых записей

Строка файла записей без завершающего перевода строки, а также строка, которая не разбирается
как запись из девяти полей, MUST NOT учитываться в счётчике. Такие строки MUST удаляться из
файла при первом обращении к очереди, чтобы очередь не блокировалась.

#### Scenario: Питание пропало посреди записи строки

- GIVEN в конце `/measurements.csv` осталась строка без перевода строки
- WHEN устройство монтирует карту или загружает очередь
- THEN эта строка не учитывается в счётчике и удаляется из файла при ремонте

#### Scenario: Неразборчивая строка в середине файла

- GIVEN файл содержит строку, не соответствующую формату записи
- WHEN устройство загружает очередь
- THEN корректные записи сохраняются и возвращаются, а неразборчивая строка удаляется

### Requirement: Безопасная замена файла очереди

Удаление отправленных записей MUST выполняться без промежутка, в котором очередь отсутствует:
сначала полностью готовится новый файл, затем текущий файл уводится в резерв, затем новый
файл становится основным. Сбой на любом шаге MUST оставлять на карте прежние записи.

#### Scenario: Сбой подстановки нового файла

- GIVEN новый файл очереди подготовлен, а подстановка его на место основного не удалась
- WHEN устройство обрабатывает ошибку
- THEN на карте остаётся прежний файл с отправленными и неотправленными записями, а счётчик пересчитывается по файлу

#### Scenario: Удаление при отсутствии файла записей

- GIVEN файла `/measurements.csv` нет
- WHEN устройство удаляет отправленные записи
- THEN операция считается успешной, а счётчик равен нулю

#### Scenario: Восстановление после обрыва во время замены

- GIVEN питание пропало после увода основного файла в резерв
- WHEN устройство монтирует карту в следующем цикле
- THEN очередь восстанавливается из подготовленного или резервного файла

### Requirement: Подтверждение добавления записи

После добавления записи устройство MUST проверять, что на карту записаны все байты строки и
что размер файла вырос ровно на длину строки. При несовпадении добавление MUST считаться
неудачным, а кэш счётчика MUST быть сброшен.

#### Scenario: Запись выполнена полностью

- GIVEN карта доступна для добавления
- WHEN строка записи записана и размер файла вырос на её длину
- THEN количество записей увеличивается на одну

#### Scenario: Запись оборвалась

- GIVEN запись строки завершилась неполно или размер файла не соответствует ожидаемому
- WHEN устройство проверяет результат добавления
- THEN добавление считается неудачным, кэш счётчика сбрасывается и счётчик пересчитывается по файлу
