# Design

## Context

В `wifi_manager.cpp` устройство уже получает hostname и параметры ThingSpeak из `device_config.h`, а список Wi-Fi точек доступа — из отдельного `wifi_config.h`. Оба заголовка выбирают настройки по `DEVICE_NUM`. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**

- Сохранить текущие данные локальной конфигурации Wi-Fi при миграции.
- Оставить единственную пару файлов: игнорируемый локальный `device_config.h` и отслеживаемый `device_config.example.h`.
- Сохранить runtime-логику выбора точек доступа и подключения без изменений.

**Non-Goals:**

- Менять последовательность или таймаут подключения Wi-Fi.
- Переписывать историю Git или отзывать секреты, ранее попавшие в репозиторий.

## Decisions

- Перенести `WiFiAP`, массивы доступа и выбранные `apList`/`apListSize` в существующие локальный и примерный заголовки конфигурации. Это оставляет используемые `wifi_manager.cpp` данные в одном месте, не меняя их интерфейс или runtime-поведение.
- Объединить пример из обоих файлов вручную, сохранив демонстрационные сети и плейсхолдеры; не копировать локальные реальные учетные данные в пример.
- Перенести реальные настройки сетей из `wifi_config.h` в локальный `device_config.h`, сохраняя строковые значения без отображения или попадания в OpenSpec/README. После успешной миграции удалить отдельный `wifi_config.h`, а также отслеживаемые `wifi_config.example.h` и обновить подключения.

## Risks / Trade-offs

- [Локальные сетевые значения могут быть потеряны при миграции] → проверить, что локальный файл содержит списки точек доступа всех поддерживаемых устройств до удаления исходного заголовка.
- [Пример станет длиннее] → сохранить единый файл рядом с локальной конфигурацией, чтобы обеспечить простую команду копирования.
- [Реальные учетные данные ранее могли присутствовать в истории Git] → не копировать их в новые примеры; при необходимости заменить ключи и пароли отдельно.

## Migration Plan

1. Перенести существующие значения сетей во все соответствующие массивы локального `device_config.h`, не перезаписывая параметры ThingSpeak.
2. Обновить пример, добавив в него сети-примеры к уже имеющимся device/ThingSpeak полям.
3. Удалить отдельные Wi-Fi заголовки и include на них; обновить инструкции о едином конфигурационном файле.
4. Проверить diff без вывода секретных значений, выполнить поиск старых имён файлов и сборку PlatformIO.

Для отката вернуть отдельные Wi-Fi заголовки из шаблона/истории и восстановить их include, не возвращая рабочие учетные данные в отслеживаемые файлы.
