# Жизненный цикл устройства

## Purpose

Описать запуск устройства, подключение к сети и времени, пробуждение и переход в deep sleep.

## Requirements

### Requirement: Подключение к Wi-Fi с офлайн-режимом

При старте устройство MUST последовательно проверять настроенные точки доступа, выделяя до пяти секунд на каждую попытку. Если подключение не удалось, устройство MUST продолжить автономную работу с доступными датчиками, RTC и SD-картой.

#### Scenario: Точка доступа доступна

- GIVEN список точек доступа содержит доступную сеть
- WHEN устройство выполняет подключение
- THEN оно подключается в режиме станции и продолжает обычный сценарий запуска

#### Scenario: Ни одна точка доступа недоступна

- GIVEN все настроенные попытки подключения завершились неудачно
- WHEN запуск продолжается
- THEN устройство отмечает Wi-Fi как недоступный и работает офлайн

### Requirement: Использование локального времени RTC

Устройство MUST использовать DS3231 для хранения локального времени MSK (UTC+3). При обнаружении потери питания RTC во время обычного запуска устройство MUST попытаться получить время от настроенных NTP-серверов и записать первое полученное время в RTC. Если Wi-Fi недоступен, устройство MUST продолжить работу с имеющимся временем RTC. В записи измерения MUST использоваться UTC Unix timestamp.

#### Scenario: RTC потерял питание и NTP доступен

- GIVEN обычный запуск обнаружил потерю питания RTC и Wi-Fi подключен
- WHEN один из настроенных NTP-серверов предоставляет время
- THEN устройство устанавливает полученное локальное время в DS3231 и использует UTC timestamp для измерения

#### Scenario: RTC потерял питание, но Wi-Fi недоступен

- GIVEN обычный запуск обнаружил потерю питания RTC, но подключения к Wi-Fi нет
- WHEN устройство продолжает автономный запуск
- THEN оно использует текущее время RTC без синхронизации по NTP

### Requirement: Пробуждение и переход в deep sleep

Устройство MUST увеличивать счетчик пробуждений, хранящийся в RTC-памяти, и после обработки одного измерения переходить в deep sleep. Таймер пробуждения MUST быть установлен на 60 секунд; также MUST быть настроено пробуждение кнопками GPIO0 через EXT0 и GPIO35 через EXT1 с условием ALL_LOW.

#### Scenario: Таймерное пробуждение

- GIVEN устройство находится в deep sleep
- WHEN истекают 60 секунд
- THEN ESP32 просыпается, увеличивает счетчик пробуждений и запускает цикл измерения

#### Scenario: Пробуждение кнопкой

- GIVEN устройство находится в deep sleep
- WHEN срабатывает кнопка, настроенная на GPIO0 или GPIO35
- THEN ESP32 просыпается и выполняет сценарий запуска

### Requirement: Измерение напряжения питания

Устройство MUST измерять USB и аккумулятор через ADC GPIO34 с коэффициентом преобразования `ADC * 7.26 / 4095`. Для измерения аккумулятора MUST включать цепь через GPIO14, после измерения MUST выключать ее. USB MUST считаться подключенным при напряжении не ниже 4.5 В.

#### Scenario: Измерение источников питания

- GIVEN устройство выполняет измерение питания
- WHEN сначала считывается USB, а затем аккумулятор
- THEN результат содержит оба напряжения, а флаг зарядного устройства соответствует порогу 4.5 В

### Requirement: Переключение режима дисплея при пробуждении кнопкой
После пробуждения устройства нажатием любой кнопки устройство MUST проверять, удерживается ли вторая кнопка GPIO35 в течение одной секунды. При подтвержденном удержании устройство MUST переключить и постоянно сохранить выбранный режим дисплея и показать сообщение `display on` или `display off` в течение одной секунды. При пробуждении по таймеру устройство MUST пропускать эту проверку.

#### Scenario: Удержание второй кнопки при кнопочном пробуждении
- GIVEN устройство пробудилось от GPIO0 или GPIO35, а вторая кнопка GPIO35 удерживается
- WHEN устройство подтверждает удержание в течение одной секунды
- THEN оно переключает и сохраняет режим дисплея и отображает соответствующее сообщение `display on` или `display off` в течение одной секунды

#### Scenario: Вторая кнопка не удерживается достаточно долго
- GIVEN устройство пробудилось от GPIO0 или GPIO35
- WHEN вторая кнопка GPIO35 не удерживается в течение одной секунды
- THEN сохраненный режим дисплея остается без изменений

#### Scenario: Пробуждение по таймеру
- GIVEN устройство пробудилось по таймеру
- WHEN устройство начинает запуск
- THEN оно не проверяет GPIO35 для переключения режима и не меняет сохраненный режим

### Requirement: Применение сохраненного режима дисплея
При запуске устройства MUST применить ранее сохраненный режим дисплея и сохранить его между отключениями питания. Режим MUST управлять отображением при обычном и таймерном запуске, но пробуждение любой кнопкой MUST включать дисплей на текущий цикл. Новое значение, выбранное при текущем запуске, MUST влиять на управление дисплеем при следующем запуске.

#### Scenario: Следующий запуск применяет режим выключенного дисплея
- GIVEN при предыдущем запуске был выбран режим `display off`
- WHEN устройство запускается снова
- THEN дисплей остается выключенным, в том числе при пробуждении по таймеру с подключенным USB

#### Scenario: Кнопочное пробуждение включает дисплей в режиме off
- GIVEN сохранен режим `display off` и устройство находится в deep sleep
- WHEN устройство пробуждается по нажатию любой кнопки
- THEN дисплей включается и остается включенным в течение текущего цикла, а режим `display off` применяется при следующем переходе в deep sleep

#### Scenario: Следующий запуск применяет режим включенного дисплея
- GIVEN при предыдущем запуске был выбран режим `display on`
- WHEN устройство запускается снова
- THEN дисплей остается включенным, в том числе при пробуждении по таймеру без USB-питания

#### Scenario: Новое значение не меняет режим текущего запуска
- GIVEN устройство пробудилось кнопкой и пользователь переключил режим дисплея
- WHEN устройство продолжает текущий цикл после сообщения о выбранном режиме
- THEN обычное поведение дисплея текущего цикла не меняется, а выбранный режим применяется при следующем запуске
